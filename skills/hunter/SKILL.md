# Hunter · 全网素材搜集

## 什么时候用

用户说"帮我搜集 XX 的资料/素材""调研一下 XX""找找关于 XX 的内容"时，用这个 skill。输出是一份结构化的素材清单，不是结论——筛选交给 `curator`。

## 输入

- 主题（一句话）
- 用途：写文章 / 做视频 / 做图片 / 纯了解（决定搜集的颗粒度）
- 语言偏好：中文优先 / 英文优先 / 都要
- 数量要求（默认 15–30 条）

## 工作流

### 1. 拆关键词

把主题拆成 3–5 组中英关键词，包括：正式名称、俗称/别名、相关事件词。英文关键词必须有一组——很多一手资料只有英文。

### 2. 多路并行搜集

按顺序覆盖这几路，每路记下用了什么关键词：

1. **Web 搜索**：通用搜索打底，抓综述类、百科类、媒体报道。
2. **新闻/时效**：主题有时效性时单独搜新闻，标注发布时间。
3. **社媒与社区**：找真实用户的讨论、经验帖、避坑帖（注明是个人观点）。
4. **官方一手源**：官网、官方文档、官方公告——优先级最高。
5. **订阅源**：如果用户有 RSS/信息流（如 FreshRSS），顺手扫一遍相关订阅。

### 3. 逐条记录

每条素材记录六项，缺一不可：

| 标题 | 链接 | 来源 | 发布时间 | 一句话摘要 | 类型 |
|---|---|---|---|---|---|
| | | | | | 一手/二手/个人观点 |

### 4. 粗去重

同一事件的多家转载合并为一条（保留最早或最全的）；同一来源的多篇相关文章保留 2–3 篇代表作。

### 5. 输出素材清单

按"一手来源 → 权威媒体 → 社区讨论"的顺序排列，顶部加一段 3–5 行的搜集说明：覆盖了哪些渠道、时间范围、有没有明显的信息缺口。

## 输出模板

```markdown
# 素材清单：<主题>
搜集时间：<日期>；渠道：<列出>；共 <N> 条（去重后）

## 一手来源
| 标题 | 链接 | 时间 | 摘要 |

## 媒体报道
| 标题 | 链接 | 时间 | 摘要 |

## 社区讨论
| 标题 | 链接 | 时间 | 摘要 |

## 信息缺口
- <没找到、或需要进一步核实的内容>
```

## 注意事项

- 区分事实和观点：个人经验帖必须标注"个人观点，未经核实"。
- 时间敏感信息（价格、政策、版本）必须标注检索日期，过期风险要明说。
- 不要在搜集阶段下结论、做推荐——那是 curator 和正文写作的事。
- 搜不到时如实说"没找到"，不要编链接。
